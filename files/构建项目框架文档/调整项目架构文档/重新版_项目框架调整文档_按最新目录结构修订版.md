# 基于 Agent 的 Web 高级编程管理平台——项目框架调整文档（按最新目录结构修订版）

> 版本：V4.0  
> 适用对象：当前 Spring Boot + Vue 前后端分离项目  
> 修订重点：基于你调整后的项目整体结构重新整理，保留“数据库统一建模”，但在前端页面、前端 API、后端业务包、运行文件目录上尽量做到清晰分区，方便 Python 实验、Vue 实验、大作业、课程闭环模块分别开发和维护。

---

## 1. 本次调整的核心结论

本项目最终建议采用：

```text
前端业务目录分开
后端业务模块分开
数据库表结构统一
文件存储目录统一管理但按业务分类
界面菜单仍然保持教学逻辑上的统一
```

也就是说：

1. **界面上不把 Python 实验和 Vue 实验拆成两个一级菜单**  
   教师端和学生端仍然保留“实验”一级菜单，下面再分为“Python 实验”和“Vue 实验”。

2. **代码上 Python 实验和 Vue 实验必须切开**  
   前端页面目录、前端 API 文件、后端 Controller、Service、DTO、VO、运行逻辑都分别放在独立目录下。  
   两个开发者不应该频繁修改同一个业务文件。

3. **数据库层面不切成两套实验表**  
   实验任务、提交记录、实验成绩等公共数据仍然使用统一表。  
   Python 特有数据放 Python 扩展表，Vue 特有数据放 Vue 扩展表。

4. **文件模块要分清“项目文档文件”和“运行期业务文件”**  
   `files/` 建议作为项目文档、模板、样例文件目录。  
   `storage/` 建议作为运行期上传、解压、截图、导出结果目录。  
   不建议把学生上传代码、截图、导出文件直接混放在项目文档目录中。

5. **成绩计算不建议用数据库触发器**  
   Python 实验和 Vue 实验最终都写入统一的 `experiment_score`。  
   课程闭环模块通过业务服务统一计算实验平均分、总成绩、课程目标达成度和报表导出。

## 3. 后端结构调整方案

### 3.1 后端改造原则

后端建议保持单个 Spring Boot 工程，不建议一开始拆成多个后端服务。原因是本项目属于课程大作业场景，所有模块都围绕《Web 高级编程》这一门课，并且用户、班级、课程、成绩、文件、Agent 等能力需要统一管理。

后端内部采用：

```text
单体 Spring Boot 应用
按业务模块分包
数据库 Entity/Mapper 统一管理
Python/Vue 业务逻辑完全分开
```

### 3.2 后端包结构总览

### 3.3 为什么 Entity/Mapper 可以统一，而业务模块必须分开

你的要求是 Python 和 Vue 在前端、后端上尽量完全分开；但数据库层面不准备完全分开。因此建议这样处理：

| 层级 | 是否分开 | 原因 |
|---|---|---|
| Controller | 必须分开 | Python 和 Vue 接口语义不同，避免互相影响 |
| Service | 必须分开 | Python 判题和 Vue 截图流程完全不同 |
| DTO/VO | 必须分开 | 请求字段、返回字段不同 |
| Runner/Executor | 必须分开 | Python 运行代码和 Vue 启动项目不是一类流程 |
| Entity/Mapper | 可以统一管理 | 数据库公共表统一，便于成绩汇总 |
| 数据库表 | 适当分离 | 公共主表统一，专属字段单独扩展 |

也就是说，**业务代码层面切开，数据库访问层面允许统一**。这样既能满足团队分工，也能避免最后成绩统计变复杂。

### 4.3 成绩汇总逻辑

课程闭环模块只认三类成绩：

```text
作业成绩：教师手动导入
实验成绩：从 experiment_score 统一计算平均分
大作业成绩：从 project_score 读取最终复核分
```

推荐流程：

```text
Python/Vue 实验评分完成
        ↓
写入 experiment_score.final_score
        ↓
教师点击“同步实验成绩”
        ↓
CourseScoreCalculateService 计算所有实验平均分
        ↓
写入 course_student_score.experiment_score
        ↓
同步大作业成绩、作业成绩
        ↓
计算总成绩
        ↓
生成成绩明细表和课程质量评价资料汇编
```

不建议用数据库触发器自动算平均分，因为触发器不利于调试，也不利于展示业务流程。建议使用业务层服务方法统一计算。

## 12. 数据库统一后的成绩流转

本项目数据库不拆成两套实验成绩表，最终成绩流转如下：

```text
Python 实验
    ↓
experiment_task(type = PYTHON)
experiment_submission
exp_python_test_case
exp_python_case_result
experiment_score

Vue 实验
    ↓
experiment_task(type = VUE)
experiment_submission
exp_vue_run_config
exp_vue_screenshot
experiment_score

课程闭环模块
    ↓
读取 experiment_score
计算实验平均分
写入 course_student_score.experiment_score
```

### 12.1 实验平均分计算建议

不使用触发器，使用业务层方法：

```java
public void refreshExperimentAverageScore(Long courseId) {
    // 1. 查询课程下所有已发布实验
    // 2. 查询每个学生在 experiment_score 中的最终分
    // 3. 按学生分组计算平均分
    // 4. 写入 course_student_score.experiment_score
}
```

计算规则建议：

```text
实验平均分 = 学生所有已评分实验 final_score 的平均值
```

如果要区分 Python 和 Vue 权重，可在后续增加实验任务权重字段，但当前版本建议先用简单平均，符合你最初的设计。

## 17. 最终落地建议

最终项目不要追求“所有东西都完全拆开”，而是要把“需要多人协作的业务代码”拆开，把“必须统一的数据和基础能力”统一起来。

推荐最终边界如下：

```text
界面：
实验是一级菜单，Python 实验和 Vue 实验是二级菜单。

前端：
Python 和 Vue 页面、API、组件分开。

后端：
Python 和 Vue Controller、Service、DTO、VO、Runner 分开。

数据库：
实验主表、提交表、成绩表统一；Python/Vue 差异化数据用扩展表。

文件：
files 放项目文档和模板；storage 放运行期上传、解压、截图、导出文件。

成绩：
Python/Vue 都写 experiment_score；课程闭环模块统一计算实验平均分和总成绩。

Agent：
module/ai 提供基础能力；大作业模块重点调用；实验模块按需调用。
```

这样调整后，项目会更适合课程答辩展示：

1. 能体现前后端分离。
2. 能体现 Python 实验和 Vue 实验两人并行开发。
3. 能体现数据库统一建模和成绩闭环。
4. 能体现文件上传、截图、Agent 评测、报表导出的完整工程能力。
5. 不会因为过度拆分导致联调困难。
