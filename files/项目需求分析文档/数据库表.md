# 基于 Agent 的 Web 高级编程管理平台——全新版数据库表设计文档（V2.0 适当分离版）

> 适用项目：基于 Agent 的 Web 高级编程管理平台  
> 数据库：MySQL 8.x  
> 字符集：utf8mb4  
> 设计重点：课程闭环成绩汇总、Python 实验自动判题、Vue 实验运行截图、大作业 Agent 智能评测  
> 核心原则：**实验模块在业务上统一，在数据库上适当分离，在成绩汇总上统一归口。**

---

## 1. 总体结论

### 1.1 Python 实验和 Vue 实验数据库是否完全分离？

不建议完全分离成两套互不相关的实验表。

也不建议所有字段都塞进同一张大表。

本项目最合适的方案是：

```text
统一实验主表 + Python 专属子表 + Vue 专属子表 + 统一实验成绩表
```

也就是：

```text
实验公共层：
- experiment_task
- experiment_submission
- experiment_score

Python 专属层：
- exp_python_test_case
- exp_python_case_result

Vue 专属层：
- exp_vue_run_config
- exp_vue_screenshot

课程成绩汇总层：
- course_student_score
```

这样既能让 Python 实验和 Vue 实验两个开发人员在数据库和代码上分工明确，又能保证最后“所有实验成绩求平均”时非常简单。

---

## 2. 为什么不能完全拆成两套实验表

不推荐这样设计：

```text
python_experiment_task
python_experiment_submission
python_experiment_score

vue_experiment_task
vue_experiment_submission
vue_experiment_score
```

原因如下：

| 问题 | 说明 |
|---|---|
| 成绩汇总麻烦 | 最后要算“全部实验平均分”，必须 UNION 两套表 |
| 学生实验列表麻烦 | 学生端要同时查 Python 和 Vue，还要自己合并排序 |
| 教师实验统计麻烦 | 实验总次数、提交人数、平均分要跨表统计 |
| 接口重复 | Python 和 Vue 都要写一遍任务、提交、成绩接口 |
| 后期扩展困难 | 如果以后加 Java 实验、Spring 实验，又要新建一整套表 |

因此，建议数据库层采用“公共主表 + 类型子表”方式。

# 6. 课程闭环与成绩管理表

本模块对应教师端的“Web 高级编程课程闭环评价与成绩管理”。

它不负责具体实验评测，也不负责大作业 Agent 执行。

它只负责：

```text
1. 课程大纲导入
2. 课程目标保存
3. 评分项保存
4. 作业成绩导入
5. 同步实验平均分
6. 同步大作业最终分
7. 计算总成绩
8. 计算课程目标达成度
9. 导出成绩明细表
10. 生成课程质量评价资料汇编
```

## 6.1 课程表 course

```sql
CREATE TABLE course (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '课程ID',
    course_name VARCHAR(128) NOT NULL DEFAULT 'Web 高级编程' COMMENT '课程名称',
    course_code VARCHAR(64) DEFAULT NULL COMMENT '课程编号',
    semester VARCHAR(64) DEFAULT NULL COMMENT '学期',
    credit DECIMAL(4,1) DEFAULT NULL COMMENT '学分',
    total_hours INT DEFAULT NULL COMMENT '总学时',
    theory_hours INT DEFAULT NULL COMMENT '理论学时',
    experiment_hours INT DEFAULT NULL COMMENT '实验学时',
    teacher_id BIGINT DEFAULT NULL COMMENT '任课教师ID',
    class_id BIGINT DEFAULT NULL COMMENT '授课班级ID',
    status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/ARCHIVED',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_course_semester (semester),
    INDEX idx_course_teacher (teacher_id),
    INDEX idx_course_class (class_id),
    CONSTRAINT fk_course_teacher FOREIGN KEY (teacher_id) REFERENCES teacher(id),
    CONSTRAINT fk_course_class FOREIGN KEY (class_id) REFERENCES class_info(id)
```

## 6.4 评分项表 assessment_item

本项目默认有三个评分项：

```text
作业成绩：30 分，教师导入
实验成绩：20 分，由实验模块平均分折算
大作业成绩：50 分，由大作业模块最终分折算
```

```sql
CREATE TABLE assessment_item (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '评分项ID',
    course_id BIGINT NOT NULL COMMENT '课程ID',
    item_name VARCHAR(64) NOT NULL COMMENT '评分项名称：作业/实验/大作业',
    item_type VARCHAR(32) NOT NULL COMMENT 'HOMEWORK/EXPERIMENT/PROJECT',
    full_score DECIMAL(6,2) NOT NULL COMMENT '该项满分，如30、20、50',
    weight DECIMAL(5,2) NOT NULL COMMENT '权重，如0.30、0.20、0.50',
    source_type VARCHAR(32) NOT NULL COMMENT 'MANUAL/EXPERIMENT_MODULE/PROJECT_MODULE',
    sort_order INT NOT NULL DEFAULT 0 COMMENT '排序',
    description TEXT DEFAULT NULL COMMENT '说明',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_assessment_course (course_id),
    UNIQUE KEY uk_course_item_type (course_id, item_type),
    CONSTRAINT fk_assessment_course FOREIGN KEY (course_id) REFERENCES course(id)
) COMMENT='课程评分项表';
```

## 6.5 课程目标与评分项映射表 objective_assessment_map

该表用于课程目标达成度计算。

示例：


```sql

    objective_id BIGINT NOT NULL COMMENT '课程目标ID',

    objective_score DECIMAL(6,2) NOT NULL COMMENT '该评分项分配给该课程目标的满分',
    description TEXT DEFAULT NULL COMMENT '说明',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_map_course (course_id),
    INDEX idx_map_objective (objective_id),
    INDEX idx_map_item (assessment_item_id),
    UNIQUE KEY uk_objective_item (objective_id, assessment_item_id),
    CONSTRAINT fk_map_course FOREIGN KEY (course_id) REFERENCES course(id),
    CONSTRAINT fk_map_objective FOREIGN KEY (objective_id) REFERENCES course_objective(id),
    CONSTRAINT fk_map_item FOREIGN KEY (assessment_item_id) REFERENCES assessment_item(id)

```

# 12. 成绩计算与同步策略

## 12.1 是否使用数据库触发器？

不建议用触发器自动计算最终成绩。

建议使用：

```text
Spring Boot Service 层显式同步
```

原因：

| 方案 | 优点 | 缺点 | 本项目建议 |
|---|---|---|---|
| 数据库触发器 | 自动执行，不依赖接口是否调用 | 难调试、难追踪、跨多表统计复杂、业务变化后难维护 | 不推荐 |
| Service 层同步 | 逻辑清楚、方便调试、方便展示、方便人工重算 | 需要主动调用同步接口 | 推荐 |
| 定时任务同步 | 可自动补偿漏算 | 实时性较弱 | 可作为补充 |
| SQL 视图 | 展示方便 | 不适合保存锁定成绩 | 可辅助查询 |

最终建议：

```text
实验成绩确认
→ ExperimentScoreService.confirmScore()
→ CourseScoreSyncService.syncExperimentScore(courseId, studentId)

大作业成绩确认
→ ProjectScoreService.confirmScore()
→ CourseScoreSyncService.syncProjectScore(courseId, studentId)

作业成绩导入
→ HomeworkImportService.importScore()
→ CourseScoreSyncService.syncHomeworkScore(courseId, studentId)

教师点击重新计算
→ CourseScoreSyncService.recalculateAll(courseId)
```

---

## 12.2 实验平均分计算规则

你现在的业务规则是：

```text
实验成绩 = 所有实验成绩相加 / 全部实验次数
```

因此要注意：分母应该是“已发布且计入成绩的实验任务数”，而不是“学生已经提交的实验数”。

这样缺交实验才会自然记为 0 分。

### 推荐 SQL：按全部已发布实验计算平均分

```sql
SELECT
    st.id AS student_id,
    ROUND(SUM(COALESCE(es.final_score, 0)) / COUNT(et.id), 2) AS experiment_raw_avg
FROM student st
JOIN course c ON c.class_id = st.class_id
JOIN experiment_task et
    ON et.course_id = c.id
   AND et.status = 'PUBLISHED'
   AND et.required_flag = 1
LEFT JOIN experiment_score es
    ON es.experiment_id = et.id
   AND es.student_id = st.id
   AND es.score_status = 'CONFIRMED'
WHERE c.id = ?
GROUP BY st.id;
```

### 折算为课程中的实验成绩

如果课程大纲中实验成绩占 20 分：

```text
experiment_score = experiment_raw_avg / 100 × 20
```

对应 SQL：

```sql
UPDATE course_student_score csc
JOIN (
    SELECT
        st.id AS student_id,
        ROUND(SUM(COALESCE(es.final_score, 0)) / COUNT(et.id), 2) AS raw_avg
    FROM student st
    JOIN course c ON c.class_id = st.class_id
    JOIN experiment_task et
        ON et.course_id = c.id
       AND et.status = 'PUBLISHED'
       AND et.required_flag = 1
    LEFT JOIN experiment_score es
        ON es.experiment_id = et.id
       AND es.student_id = st.id
       AND es.score_status = 'CONFIRMED'
    WHERE c.id = #{courseId}
    GROUP BY st.id
) t ON csc.course_id = #{courseId}
   AND csc.student_id = t.student_id
SET
    csc.experiment_raw_avg = t.raw_avg,
    csc.experiment_score = ROUND(t.raw_avg / 100 * 20, 2),
    csc.updated_at = NOW();
```

## 12.3 大作业成绩同步规则

大作业按 100 分制保存，课程成绩中折算为 50 分。

```text
project_score = project_raw_score / 100 × 50
```

如果存在教师复核分，以教师复核分为准；否则可使用 Agent 建议分，但建议最终仍由教师确认。

```sql
UPDATE course_student_score csc
JOIN project_score ps
    ON ps.student_id = csc.student_id
JOIN project_assignment pa
    ON pa.id = ps.assignment_id
   AND pa.course_id = csc.course_id
SET
    csc.project_raw_score = ps.final_score,
    csc.project_score = ROUND(ps.final_score / 100 * 50, 2),
    csc.updated_at = NOW()
WHERE csc.course_id = #{courseId}
  AND ps.score_status = 'CONFIRMED';
```

## 12.4 作业成绩同步规则

作业成绩来自教师手动导入，满分 30，直接写入课程成绩表。

```sql
UPDATE course_student_score csc
JOIN homework_score_detail hsd
    ON hsd.course_id = csc.course_id
   AND hsd.student_id = csc.student_id
SET
    csc.homework_score = hsd.homework_score,
    csc.updated_at = NOW()
WHERE csc.course_id = #{courseId}
  AND hsd.batch_id = #{batchId}
  AND hsd.import_status = 'SUCCESS';
```

## 12.5 总成绩计算

```text
total_score = homework_score + experiment_score + project_score
```

```sql
UPDATE course_student_score

        + COALESCE(experiment_score, 0)

        2
    ),
    score_status = 'CALCULATED',
    last_calculated_at = NOW(),
    updated_at = NOW()
WHERE course_id = #{courseId};
```

## 12.6 课程目标达成度计算

假设映射关系为：

```text
课程目标1：作业30 + 大作业20
课程目标2：实验20 + 大作业30
```

则：

```sql
UPDATE course_student_score
SET
    objective1_score = ROUND(
        COALESCE(homework_score, 0)
        + COALESCE(project_score, 0) * 20 / 50,
        2
    ),
    objective2_score = ROUND(
        COALESCE(experiment_score, 0)
        + COALESCE(project_score, 0) * 30 / 50,
        2
    ),
    objective1_achieved = CASE
        WHEN ROUND(COALESCE(homework_score, 0) + COALESCE(project_score, 0) * 20 / 50, 2) >= 35
        THEN 1 ELSE 0 END,
    objective2_achieved = CASE
        WHEN ROUND(COALESCE(experiment_score, 0) + COALESCE(project_score, 0) * 30 / 50, 2) >= 35
        THEN 1 ELSE 0 END,
    updated_at = NOW()
WHERE course_id = #{courseId};
```

说明：

```text
课程目标1满分50，达成阈值70%，所以阈值为35。
课程目标2满分50，达成阈值70%，所以阈值为35。
```

后期如果要更通用，可以完全基于 `objective_assessment_map` 动态计算，而不是写死两个目标。

# 16. 最终落地建议

本项目的数据库不要追求“完全拆开”，而要追求“职责清楚”。

最终建议可以概括为：

```text
1. Python 和 Vue 在代码目录上分开，方便两个人开发。
2. Python 和 Vue 在数据库上共用实验任务、提交、成绩三张主表。
3. Python 专属测试用例和运行结果单独建表。
4. Vue 专属运行配置和截图结果单独建表。
5. 课程闭环只读取 experiment_score，不关心 Python 和 Vue 内部怎么跑。
6. 实验平均分由 Spring Boot Service 层同步，不建议使用数据库触发器。
7. 教师端点击“同步实验成绩”或“重新计算”时，可以重新计算全部学生成绩。
```

一句话总结：

```text
文件夹可以完全分开，数据库不要完全割裂；实验成绩必须统一出口，最终都进入 experiment_score，再同步到 course_student_score。
```
